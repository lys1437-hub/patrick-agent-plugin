# 完成條件與發布範本

> 上半是規則，下半是可複製到團隊 repo `.github/PULL_REQUEST_TEMPLATE.md` 的片段。本檔是 PR 描述格式的唯一正本；[方法文件](README.md) §1.3 寫原則、§1.4 指向本檔。

## 規則

### 每個 PR 都要有的元素
| 元素 | 寫什麼 | 證據 |
|---|---|---|
| 真實使用情境 | 誰、在什麼情況下用到這次變更 | — |
| 反例與邊界 | 不該發生的情況、邊界輸入 | 每個反例對應的證據 |
| 完成條件對證據 | 每條完成條件一列，寫成可觀測的結果（方法文件 §1.3） | 程式或行為：可重跑的測試或步驟與輸出；純文件：對讀表＋渲染結果 |
| 需求驗收 | 指向產品 owner 本人驗收紀錄（含結果與時間）的指標；作者兼產品 owner 時，由團隊決策者另指定非作者的驗收人（方法文件 §1.6 第 7 項） | 驗收紀錄 |

- **純文件不硬套測試**：證據改用「對讀表（新文字 ↔ 依據出處）」與「渲染結果」。
- **CI 必跑項**由 repo 技術 owner 明訂，寫在 repo 的規則檔；PR 不自行增減。

### 表一：級別 → 批准與發布授權（分級見方法文件 §1.8）
| 級別 | 非作者批准 | 發布授權 |
|---|---|---|
| T-low | 任一非作者 builder | 無正式環境影響：不適用；有：產品 owner＋RD |
| T-mid | 非作者 RD | 產品 owner＋RD |
| T-high | RD code owner（後端／前端；跨端兩組各一位；不屬前後端目錄的路徑（規則檔、CI 設定、Skill、憑證相關等），由團隊決策者指定負責的組，指定前照跨前後端處理） | 另經授權 |

### 表二：正式環境影響 → 附加欄位
| production_impact | staging 驗證 | 回復方式 | 責任人 |
|---|---|---|---|
| 有 | 必填 | 必填 | 必填 |
| 無 | 寫「不列入」＋理由 | 寫「不列入」＋理由 | 寫「不列入」＋理由 |
| 待 RD 判定 | RD 判定前不得合併 | 同左 | 同左 |

- 正式環境影響逐案填，不由級別推定；純文件沒有可部署對象時，表二寫「不列入」＋理由，表一的發布授權仍照表一判定（T-low 依正式環境影響分兩種），不整組免除。
