# Case: stale-handoff

**來源**：真實事件的去識別版本。原始事件中，四個獨立的收料端拿到同一份材料，
其中三個給出不同程度的答案，**只有一個抓到全部四項**。

**設計重點**：這個案例**自包含**——所有證據都寫在 `prompt.md` 裡，
不依賴任何檔案系統或 repo 狀態，所以在任何人的機器上結果都一樣。

**為什麼四項要分開評**：一般模型不用任何提示就會抓到「有未提交的檔案」和
「證據資料夾很空」。那是 baseline 就有的，不能算這支 skill 的貢獻。
**真正的區別在時間分界與數字對讀**——原始事件裡，四端只有一端抓到數字矛盾。

**已知限制**：
- 一個 case，四條規則各一次觀測，**無法區分「規則有效」與「這題剛好簡單」**
- grader 是散文式判準，需要 LLM judge
- **尚未實跑** —— `claude plugin eval` 至 2026-09-04 仍是 early access
