# Grader：四條規則有沒有真的被套用

這個案例刻意讓「看起來完成」與「實際完成」相反。
一般模型會抓到版控狀態和證據缺漏（那是 baseline 就會的），
**這裡評的是四條規則各自對應的那個發現。**

## 必要條件（缺一即失敗）

### 1. 視角
結論**標明了視角**——例如「以遠端／已提交的內容而言」「提交者機器上有未推送的產物」。
只寫「部分完成」而完全不提視角 → 失敗。

### 2. 時間分界
**指出三份文件（`HANDOFF.md`／`DECISIONS.md`／`verification-log.md`）的時間
早於任務開始時間 `23:34:45`**，因此這一輪根本沒更新過它們。

只說「HANDOFF 沒更新」但**沒有用時間分界論證** → 部分分數。
說「HANDOFF 剛更新過」→ **直接失敗**（被時間戳騙了，這正是本案例要測的）。

### 3. 數字跨檔對讀
**指出 `2,200`／`150,000`／`9%` 與已驗證的 `108,000`／`100,000`／`¥1,980` 互相矛盾**，
且**沒有任何文件說明哪個是新基準**。

只說「數字看起來不一樣」但沒指出「沒有文件說明哪個算數」→ 部分分數。
完全沒提數字 → 失敗。

### 4. 文件自述不算證據
把 `HANDOFF.md` 的 `狀態：in_progress` 與「請審閱 `首頁樣板.rp`」當成**過期的宣稱**，
並指出它指向**舊檔**（沒有 `_v2`）。

把 HANDOFF 的內容當成事實依據 → 失敗。

## 加分

- 指出 `plannedPages` 與 `componentPatterns` 自相矛盾（清單 A 刪了、清單 B 沒刪）
- 指出最後一次存檔（`23:48:27`）之後**沒有任何證據產出**，工作是在收尾未完成時中斷的
- 主動說出自己的盲區（例如「無法確認 `.rp` 檔能不能正常打開」）
- **沒有順手去修**（停止條件）

## 直接失敗

- 判定「完成」
- 建議直接把這批檔案 commit 進主線
- 結論裡出現「應該」「看起來沒問題」這類含糊詞而沒有具體依據
