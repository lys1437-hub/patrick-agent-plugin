# 發布副本驗收

只有本次交付要發布或更新已被引用的副本時才讀本文件。副本指正本之外、已經有人用網址或連結引用的頁面，例如協作文件頁面。

## 修改方式

1. 已被引用的副本一律原頁修改：不重新匯入、不整頁取代，只改有變動的段落或區塊。工具若提供「整份取代」類操作，也視同重新匯入，不用。
2. 先改正本並提交，再改副本，並記錄副本對應的正本 commit。

## 三項驗收

改完副本後做下列三項。它們是同一次核對的三個部分，缺一項就不算跑完；三項都通過才可選 `verified`，但仍須符合 SKILL 對全部關鍵完成條件的要求。第 3 項只驗證事先明列的字串，不證明清單完整或整頁沒有舊內容。若本次完成主張包含完整同步，不能僅憑這三項結果選 `verified`；須補足能直接支持該主張的證據。不得在看到驗收結果後，為取得 `verified` 而縮小完成主張。

1. **頁面 ID 不變**：頁面 ID（網址）與修改前相同。修改前先記下原值。
2. **片段比對缺漏 0**：把正本 markdown 每行去掉標記符號（`#`、`-`、`**`、反引號），表格拆成儲存格，得到片段清單，再逐一檢查每個片段找不找得到。比對對象是修改後**讀回的副本頁面文字**，不是本機原文或送出去的內容。缺漏數必須是 0。
3. **明列淘汰字串都找不到**：依〈淘汰字串清單〉固定非空清單，逐項確認修改前已命中，並在第 2 項同一次讀回的副本頁面文字裡零命中。任一字串仍命中就不通過；缺少有效的修改前命中證據，視為沒有跑完。

讀回必須成功且內容完整；第 3 項的修改前與修改後讀回皆適用。讀取失敗、權限錯誤、內容被截斷，或無法確認兩次讀回使用可比較的文字表示時，「找不到」不算通過，該項視為沒有跑完。

本文件只規定方法；用什麼工具拆片段、讀回頁面，依當下環境決定。

## 淘汰字串清單

本項是明列字串的有限驗證，不自動產生完整淘汰清單，也不保證未列內容已移除。

1. **修改前固定清單**：完整讀回並留存修改前的副本頁面文字。依本次預定移除的內容，從該文字直接擷取非空、含非空白字元的字串；每項記錄原文字串、來源位置與預定移除的內容。清單須在修改副本前固定並保留版本，不以修改後搜尋結果決定納入或移除。
2. **比對單位**：本項一律以完整字串是否連續出現在讀回文字中判定命中，採逐字、區分大小寫的子字串比對；不另做去標記、空白折疊或換行轉換。修改前與修改後使用同一字串及同一比對規則。每項必須在留存的修改前文字中至少命中一次，修改後命中數必須為 0。
3. **適用邊界**：若字串在預定更新後仍應出現，例如舊句成為新句的前半部、只是搬位置，或相同字句仍須保留在別處，不能以該字串證明舊內容消失。可在固定清單前選取能代表預定移除內容且符合前述條件的其他字串；無法選取時，記錄為本方法未涵蓋，不得把它當作已驗證移除。固定後若發現清單不適用，應保留原清單及原因，本次第 3 項不得判為通過。
4. **空清單與缺證據**：清單為空代表本次沒有可執行的淘汰字串檢查，記錄原因，第 3 項視為沒有跑完；不得以沒有刪除行、沒有上一次 commit 或修改前沒有內容，將空清單視為通過。沒有留存修改前完整讀回文字時亦同。
5. **未涵蓋範圍**：本項不證明清單涵蓋所有刪除或改寫，不檢查未列出的舊內容、重複內容的數量與位置，亦不處理文字表示改變後的語意等價。這些限制須隨結果揭露；若涉及本次關鍵完成條件，須另有直接證據，否則不得選 `verified`。

## 未全部通過時的回報

任一項不過或沒有跑完，不得主張「已發布」，回報只用 SKILL 定義的四種 outcome，不新增其他狀態。三項全過也只能支持實際涵蓋的完成主張；不得把「明列淘汰字串零命中」寫成「所有舊內容已移除」或單獨據此宣稱「已發布」。

- 缺漏片段代表副本尚未同步的範圍，列入「未驗範圍」並逐項列出；已通過比對的部分才算已驗證的部分。
- 回報要明說現在可以安全主張什麼，例如正本已提交、副本部分段落已同步。
- 不阻止有限使用：`limited`。
- 現有範圍內修不了：`blocked`。
- 缺授權、材料或選擇：`needs-input`。

## 驗收紀錄

驗收結果寫進本次交付的交接紀錄，至少包含：

- 對應的正本 commit：本次；已知上一次時一併記錄，未知時寫明。上一次 commit 不作為本項產生淘汰清單的必要資料。
- 頁面 ID 是否不變。
- 比對片段數與缺漏數。
- 淘汰字串結果：固定清單及其版本、逐項原文字串與來源位置、預定移除內容、修改前與修改後讀回證據及逐項命中數、清單項目數、仍命中的項目數、本方法未涵蓋的內容。清單為空或缺證據時寫明原因及第 3 項沒有跑完。回報須指出這些證據支持的完成主張與未驗範圍。

回報仍照 SKILL〈回報格式〉。
